# 开发进度

最后更新：2026-08-22（Asia/Shanghai）

## 当前产品状态

- 产品名、图标、设计、README、隐私和启动方式已统一为首个正式版本“声作 1.0.0”。
- 三个创作入口统一为同一工作台的三种稿件结构：单段配音是一段文字和一个声音，长稿配音是整篇文稿逐句调整，多人对话是多个角色分别配声；项目页新建配音会先选择结构，不再默认跳到单段。
- 全局视觉层级收敛为窗口背景、主面板、选中面和浮层四级；正文卡片减少重复玻璃、渐变、圆角和阴影，主按钮保持实心蓝、状态使用薄荷色，信息密度更清楚但不增加页面高度。
- “可控克隆 / 极致克隆 / 描述造声”统一称为声音来源，“自然口播 / 稳健长稿”统一称为生成策略，解决两个不同概念都叫生成方式的问题。
- 左侧“更多功能”已取消折叠，长稿配音、多人对话和本地模型始终显示。
- 全局界面已内置并优先使用华为官方未修改的 HarmonyOS Sans SC 字体；字体随软件携带，不依赖系统安装，设置页与第三方许可目录保留显著声明和完整许可文本。启动时会先完成本地字体加载再绘制主界面，避免先显示系统字体、随后切换鸿蒙字体造成文字突然换行和布局跳动。
- 本地模型卡片已精简为用途、电脑要求、空间和语言四项；19 种方言改为按需查看，推荐星级继续保留。
- 单段配音统一使用 2,000 个有效字的安全上限，空格和空行不计数；超出时会提示并禁止提交。
- 单段长稿不再整段交给模型：按当前模型的安全长度和标点拆成短段，校验全文没有漏字后再合并为一个 MP3。VoxCPM2 可控克隆与极致克隆逐段缓存；失败重试只续做未完成或检查未通过的短段。
- VoxCPM2 长稿会按完整句和保守长度自动分段，过短尾句会重新均分；中文、外语和数字都按实际朗读量参与速度检查。前 2–3 个合格片段形成固定基线后还会回查开头，明显变快、变慢或变调时使用新的随机起点重做，仍严重异常则明确失败，不再把有问题的片段写成成功。长文同时使用更保守的 VoxCPM2 控制强度；同一项目、声音和表达共用稳定随机起点以减少段间声线波动，这是声作的工程稳定策略，不代表模型官方保证绝对一致。其他模型继续使用 160 字安全分段。
- 三个创作页的生成策略保持互斥二选一：“自然口播”决定日常表达和常规分段，“稳健长稿”由用户主动选择更短分段与更多重试。VoxCPM2 遇到真正长文时会在不改变“自然口播”表达的前提下自动加强底层稳定检查，不再要求用户预先判断模型风险。生成策略旁提供悬停和键盘聚焦说明；删除了与模型情绪控制重复且容易误解的“情绪演绎”策略。每个新片段都会检查时长、音量、静音、削波和语速；VoxCPM2 长稿还会比较逐段音高。可试听的轻微异常保留为警告，漏读、严重漂移、静音或损坏等不可用结果会停止当前句并保留其他已完成句子。
- 生成策略旁的问号已改为软件内可见说明，不再依赖系统 `title` 提示；鼠标悬停、点击或键盘聚焦都会显示自然口播、稳健长稿的区别，以及两者不能同时使用、情绪需另行设置。
- 项目级发音词典已增加“改读 / 跳过”两种明确规则：改读可纠正人名、品牌名和英文缩写，跳过可让精确匹配的括号、备注等不出声。规则在本机、Worker 之前按最长原文优先处理，不改项目原稿，因此 VoxCPM2、Fun-CosyVoice3 与 IndexTTS-2.5 都能稳定使用且无需模型锁；旧项目没有处理方式的规则继续按改读加载。某句完全被跳过时不会向模型发送空文字，全文都被跳过时会直接提示保留朗读内容。
- AI 文稿功能已收敛为“智能处理”：本机先固定分段与正文，API 只按 `S001…` 编号返回停顿、情绪判断和克制的表达提示，不再要求模型复述原稿，因此轻微标点差异不会让整次处理失败，API 响应中的正文也永远不能覆盖本地原稿。标注先逐段预览再保存为不朗读的项目数据，修改正文、模型或语言会自动清除旧标注。IndexTTS-2.5 逐段应用离散情绪且不叠加表达文字，Fun-CosyVoice3 与 VoxCPM2 可控克隆逐段应用表达。多人对话的“智能提取角色”继续独立保留。
- “提取台词”会先显示识别到的角色和句数，再给出清楚去向：单人内容可以留在单段配音或转到长稿配音，多人内容转到多人对话；长稿页识别到多人时也可明确选择转到多人对话或仍用一个声音，不再静默跳页或覆盖。
- 设置中的入口严格命名为“API配置”，只保留接口地址（Base URL）、模型名称（Model）和 API Key，字段后直接给出 DeepSeek 的 `https://api.deepseek.com` 与 `deepseek-v4-flash` 示例；“保存并验证”通过后立即同步到所有 API 功能，无需重开或切换页面，并明确区分配置读取失败、密钥无效、余额不足、限流和网络错误。新 Key 覆盖旧 Key。密钥由 Electron Main 使用 Windows 安全存储加密，Renderer 不能读取密钥。未配置时不影响任何本地配音功能；只有主动使用“智能处理”或“智能提取角色”时才发送对应文字，不发送录音、生成音频或本地路径。
- 所有需要文本 API 的入口统一使用闪光图标；未完成 API配置时按钮置灰且不可点击，悬停或键盘聚焦会直接说明需要到设置中配置。创建声音等纯本地操作已换用普通功能图标，避免混淆。
- 智能处理应用后不再只显示“已标注几段”：输入区会自动切到“标注结果”，在每段原文后用紫色、绿色、橙色括号分别展示情绪或语气参考、停顿和表达要求；可一键切回原文编辑，所有彩色标注只用于查看，不会被朗读。
- 主窗口默认目标尺寸从 `1760×1000` 继续提高到 `1840×1024`，并按 Windows 当前缩放后的屏幕工作区自动适配；1080P 显示器获得接近全屏但仍保留边距的创作区，小屏或高缩放环境则自动贴合可用区域，不会被任务栏挤出屏幕。最小工作流尺寸保持 1280×720（仅当屏幕本身不足时下调）。
- 已删除独立“使用帮助”页面、侧栏入口和设置中的重复帮助项，常用操作直接在对应页面表达，不保留闲置说明页面。
- 已完成一轮全界面文案审查：设置、模型下载、声音克隆、任务恢复、生成进度和常见报错只说明“现在发生了什么、下一步怎么做”，不再向用户展示断点、缓存、脱敏、安装收据、Worker 或环回端口等内部术语；新增自动测试防止这些谜语话重新出现在界面。
- 发音词典使用挂载到窗口根节点的宽版居中弹窗，不再被创作页动画容器裁切；每行可直接选择改读或跳过，规则多时只滚动规则列表，标题、保存和取消始终可见。
- 单段长稿合并改为按句号、逗号和省略号使用不同停顿，继续保留片段边缘淡化，减少机械等距停顿。
- VoxCPM2 长稿稳定链路已在 RTX 4070 上通过正式任务队列复测：284 个有效字符拆成 8 段，成品 57.928 秒；后半与前半的中位语速比为 93.65%，中位音高比为 93.31%，最大相邻音高变化 3.378 个半音。第二次运行 8 / 8 段命中经过文件哈希和质量结果复核的缓存，两份 MP3 完全一致，参考录音前后 SHA-256 不变；强制输入旧实测的 5.47 半音跳变会触发自动重做，仍异常时停止合并。
- 2026-08-22 使用 `确定版《绿联7月系统更新》_灯光.xlsx` 和现有“豆包”声音完成最终代码真实整稿复测：Excel 台词列完整读取 54 / 54 条，同一次最终任务提交生成 500.177 秒 MP3，54 / 54 段质量检查通过，6 段后台自动重做后通过，分段缓存无警告和严重问题；独立复检得到 500.168 秒、峰值 -1.49 dB、RMS -21.79 dB、削波率 0，成品 SHA-256 为 `4E9D82594024C97074A357DBF8BA985EEEBA9FE4DAD913A779827109D9B0361A`。测试同时验证失败任务重启后沿用同一任务 ID 和已完成分段续做。
- 三个创作页都提供“试听 30 字”：先对完整文字应用改读与跳过规则，再截取实际会朗读的前 30 个有效字符并明确显示，避免开头被跳过或规则跨过第 30 字时生成空试听；试听结果不保存到生成记录，也不提供导出。
- 单段、长稿和对话页按模型真实且稳定的能力锁定控制项：单段配音始终显示可控克隆、极致克隆与描述造声，VoxCPM2 三项可用；Fun-CosyVoice3 和 IndexTTS-2.5 只开放参考录音克隆，极致克隆与描述造声显示统一锁图标并提示切换到 VoxCPM2。VoxCPM2 可控克隆允许表达要求，极致克隆跟随参考录音并锁定表达，描述造声把性别、年龄感、音色、情绪和语速统一写在声音描述中；三种模式都不显示虚假的独立情绪档位。Fun-CosyVoice3 使用官方 `inference_instruct2` 提供表达要求；IndexTTS-2.5 在自然口播和稳健长稿下都可独立选择情绪与表达。情绪和表达始终保持统一双列位置，不可用时直接置灰，并与语言菜单统一使用同款锁图标和悬停提示。Main 端会再次规范化旧项目或异常请求，不能绕过界面把不支持的参数送入 Worker。

- “表达要求”统一改为常用预设下拉，提供自然清晰、轻松亲切、沉稳专业、温暖柔和、活泼有感染力和舒缓克制；选择“自定义”后才显示输入框。三个创作页共用同一控件，仍按当前模型与语言能力决定是否显示。
- 多人对话保留本机“角色名：台词”直接识别，并新增可选的 API 智能提取角色：可从分镜稿、对白稿或混杂脚本中去除场景、镜头、动作、音效和其他非台词内容，提取角色及真正说出口的台词；结果先预览再替换，详细提示词保存在 `prompts/多人对话脚本整理.md`。角色名可自定义且不限制四个角色；项目统一使用一个模型和语言，每个角色可单独设置声音、模型支持的情绪与语速，角色名不再误传为模型表达提示词。
