# 本地语音模型与长稿方案调研

核验日期：2026-10-26。以下是候选和工程判断，不代表这些模型已经集成或通过本机长稿验收。

使用范围已按用户说明调整为个人、本地、私下使用：不以商用许可作为模型筛选门槛，现有 IndexTTS-2.5 也保留在同稿比较中。仍保留上游原始说明；公开代码和便携包不包含用户样音、稿件或未经确认可再分发的模型权重。

## 结论

先修复现有生成链路，再做同稿对照。短句榜单、演示音色和发布时间不足以证明十分钟文稿不重复、不漏字或不变调；不应为了“更新”无条件替换 VoxCPM2。

## 比“整篇直接扔给模型”更重要的方案

### 个人使用还可纳入，但硬件不宜忽略

- **现有 IndexTTS-2.5**：官方版本已有情绪、时长和发音控制，支持中、英、日、西、阿语；它不是早期 IndexTTS 原版。个人使用下可以直接列入同稿听感比较，不因非商用标记排除。[官方仓库](https://github.com/index-tts/index-tts)
- **Fish Audio S2-Pro／Drama 3**：官方介绍包含多说话人、克隆和自然语言控制；Drama 3 还强调局部编辑与多轮修改。不过当前安装文档要求 S2-Pro 至少 24GB 显存，Drama 3 FP8 至少 48GB，并以 Linux／WSL 为主要环境。因此对当前 12GB 4070，这两款不是立刻装上就能稳定升级的选择；量化和原生 Windows 路线需另外验证。这是硬件／部署判断，不是商用许可筛选。[官方模型说明](https://github.com/fishaudio/fish-speech)、[官方安装要求](https://speech.fish.audio/install/)

2026 年 9 月的《Taming Long-form Text-to-Speech》指出，Qwen3-TTS、VoxCPM2 等短文表现强的自回归模型仍可能在长文退化，提出 LACI：检测错误起点后回退，并以临时约束重生成。论文给出的 Qwen3-TTS-0.6B 长文实验有明显改善，但不能推导为所有语言、模型和 Windows 部署的质量保证。[原始论文](https://arxiv.org/abs/2609.16989)

对声作的工程启发：

1. 保留自然句群和一致的说话人条件，避免机械地每句话重新开声线，也避免把有问题的生成结果递归传下去。
2. 固定合格、完整的音频／逐字稿参考。参考一旦重做，以音频哈希使依赖片段失效；不要只改文件内容却继续复用旧缓存。
3. 异常要定位到句子和时间点，只重做受影响部分；停止、退出、重新生成与断点续做不能混成同一件事。
4. 内容校对器与声学检查分开。可评估 Qwen3-ASR 与 ForcedAligner，或现有 Whisper 本地复核；识别器本身会错，品牌名、缩写、简繁体必须统一后再比较，不使用低置信度结果自动无限重试。[Qwen3-ASR 官方仓库](https://github.com/QwenLM/Qwen3-ASR)
5. LACI 的模型内部注意力约束属于研究接入方向；本轮没有把论文方法冒充已实现功能。

## 接入前的统一验收

- 同一参考录音、同一文稿和明确锁定的版本；不使用各模型各挑一条最好的演示。
- 覆盖原问题稿件、完整 Excel 旁白、中文／英文品牌名／数字混排、短标题、0.8×／1×／1.5×、长参考录音和较短录音。
- 至少多组随机种子；同时看最差样本、失败率、整句重复／漏读、滑动窗口声线稳定性、耗时和峰值资源，不能只看整篇平均音高。
- 比较用户主观试听、内容复核和声学指标，分别记录，不把某一项通过说成整体完美。
- 验证取消、排队、缓存复用、离线启动、文件导出与内存不足的中文恢复提示。
- 所有音频与文稿留在本机；不静默换用收费云服务，不把私人样音上传到演示站。

建议顺序：维护版本先稳定现有链路 → Qwen Base 小规模对照 → Nano 的 Windows ONNX 低配路线 → 根据实际长稿表现决定默认模型 → 再评估 LACI、流式试听和更重的长文模型。
