# 2026 年 11 月中文长稿模型复查

声作当前的使用场景是同一说话人连续读数分钟中文旁白，中间包含品牌名、型号与独立标题。在已保存的 8 段实录中，即使每段都通过了检查，段间语速仍有明显变化。1.0.2 先在“稳健长稿”的合并阶段处理这个可复现的问题。

| 方案         | 与这个问题相关的能力                                                                                                                                                                                                                           | 本机验证状态                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| ZONOS3-Mini  | Zyphra 于 11 月 12 日发布，支持普通话克隆和语速条件。官方给出的上下文上限对应约十分钟连续音频。语速条件按 UTF-8 字节计量，同一目标值在汉字、数字和英文混排时的表现需要单独听测。[官方发布说明](https://huggingface.co/blog/Zyphra/zonos3-mini) | 新候选，尚未接入。优先用同一段带型号的中文稿比较首尾语速、漏读和显存。 |
| IndexTTS-2.5 | 官方提供 `duration_factor` 控制生成时长。声作当前的适配器调用默认推理时长，随后使用 FFmpeg 应用用户速度。可以比较这两种路径，同一次生成只施加一次用户速度。[官方仓库](https://github.com/index-tts/index-tts)                                  | 模型已经集成。原生时长控制与当前路径的对照仍待验证。                   |
| M5-TTS       | 11 月论文介绍了中文多方言、声音克隆和 CPU 流式推理。适合考察没有独立显卡时的可用性。[原始论文](https://arxiv.org/abs/2611.10162)                                                                                                               | 候选，尚无声作本机测速或长稿试听结果。                                 |

建议优先让 ZONOS3-Mini 与现有 VoxCPM2 朗读相同参考音色、相同文稿，各保留多次生成。比较逐段语速和句内异常的位置，分别核对人名与型号，再盲听段落交界处。模型上下文长度和短句演示都无法回答这份稿件在后半段是否稳定。

本机为 RTX 4070，显存 12 GB。核对官方仓库，Fun-CosyVoice3 2512 和 IndexTTS-2.5 的权重版本与安装清单一致。VoxCPM2 的官方模型仓库有更新，清单内仅 README 内容变化，推理权重、配置和分词器一致。PyPI 的 VoxCPM 运行库当前版本仍是 2.0.3。本版在可用模型中优先选 VoxCPM2 做日常配音，跨模型测试使用相同中文句子和本地运行环境。
