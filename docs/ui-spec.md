# UI 规格

## 1. 桌面框架

- 常规 1080P 工作区目标窗口：1840×1024，并按屏幕可用区域自动收敛。
- 最小工作流窗口：1280×720；屏幕本身不足时才继续下调，1280×720 是主要验收尺寸。
- 自定义标题栏高度：50px，左侧“声作”品牌与“本地版”标识，右侧最小化/最大化/关闭。
- 左侧导航：216px；标题栏以下固定。七个核心页面不使用整页滚动，只有长文本、声音、项目、任务和记录等可增长内容在各自区域内部滚动。
- 页面内边距：24px；区块间距：20px；卡片内边距：16px。

## 2. 页面共性

每页顶部使用 26px 主标题和一句任务说明；不使用重复 eyebrow。页面级动作最多两个。正文卡片按任务从左到右或从上到下排列，避免后台管理系统式的密集表格。

## 3. 配音生成布局

- 左/中主工作区：声音来源与文本输入。“可控克隆 / 极致克隆 / 描述造声”始终同位显示；VoxCPM2 三项可用，Fun-CosyVoice3 与 IndexTTS-2.5 只开放可控克隆，另外两项置灰、显示统一锁图标，悬停或键盘聚焦提示切换到 VoxCPM2。三种模式共用同高的固定内容槽，克隆声音卡与自然语言声音描述框只替换内部可见内容，不推动下方输入区或右侧生成按钮；极致克隆警告预留固定行。
- 右侧控制列：模型、模型支持语言、当前模型真实支持的情绪或表达要求、语速、音量和固定 MP3 输出；不支持的控件不显示，语言菜单中的不支持项锁定并说明需要的模型。
- 表达要求使用高频预设下拉，默认“自然清晰”；“自定义”是最后一项，选中后在同一行显示输入框，避免增加页面高度。切回预设立即收起，不另外弹窗。
- “生成策略”问号说明使用窗口级悬浮层，不受创作卡片裁剪；靠近窗口边缘时自动换向并保持全文可见。单段配音、长稿配音和多人对话共用同一实现与文案。
- 发音词典使用宽版居中弹窗，每条规则在“改读 / 跳过”中二选一。“改读”显示“看到这些字 / 改读成”，“跳过”显示“看到这些字 / 不朗读”；旧项目中没有处理方式的规则继续按“改读”打开。说明只需告知两种规则由声作先处理、切换三款模型仍有效，不堆模型术语。规则列表单独滚动，标题及取消、保存按钮始终可见。
- 生成操作：先“试听 30 字”或正式生成；试听时选中正文框中的对应文字，并在操作区显示实际试听内容。
- 文稿操作：文字框可直接拖入 TXT、SRT、MD、Word 或 Excel；标题旁提供“智能处理”和“提取台词”。智能处理读取整篇定稿，不提供润色、精简、翻译、发音检查或自定义改写；正文先在本机固定分段，API 只按编号返回标注，弹窗再逐段显示原文、停顿、情绪和表达，确认后只保存不朗读的标注。提取台词会去除画面、动作、音效等非朗读内容；一个说话人时由用户选择留在单段配音或转到长稿配音，两个及以上说话人时建议带入多人对话。两个入口均不直接覆盖原文或强制跳页。
- 所有需要用户自备文本 API 的功能统一使用闪光图标。未完成 API配置时按钮置灰不可点击；鼠标悬停或键盘聚焦时提示前往“设置 → API配置”。本地功能不得复用该图标造成误解。
- 智能处理应用后，输入区自动切换到“标注结果”：原文保持原色，情绪或语气参考、停顿、表达要求以不同颜色的全角括号紧跟对应片段显示。用户可随时切回“原文编辑”；彩色标注只用于界面确认，绝不能拼进正文或交给模型朗读。
- 主窗口在常规 1080P 工作区默认使用 `1840×1024`，并根据 Windows 缩放后的实际可用区域自动收敛，四周保留 16px 安全距离；最小工作流尺寸优先保持 `1280×720`，屏幕本身不足时才继续缩小，避免窗口被任务栏截断。
- 底部生成条：主按钮、停止按钮和总体进度。试听结果不进入记录、不显示导出动作。
- 成功后在当前操作区显示紧凑播放器、重新生成和导出；完整记录与文件位置继续在“项目与记录”中管理，结果出现时不能把页面或主按钮向下推走。
- 单段配音、长稿配音和多人对话的项目名称统一放在页面标题操作区、保存按钮左侧，不再单独占一行。单段配音不显示重复的“准备模型 / 准备声音 / 输入文字”横向引导，三张带 1–3 标题的主卡片就是操作顺序。
- 1280×720 时单段配音、长稿配音、多人对话、我的声音、项目与记录、本地模型和设置均不使用整页纵向滚动；长稿、逐句台词、角色、声音和记录列表只在各自区域内部滚动，主要生成按钮始终可见。多人对话的角色列表必须主动让出空间给试听、生成和结果区，不能用 `overflow: hidden` 掩盖按钮。本地模型的三款模型同屏横向展示，不再把第三张卡片挤到首屏下方。

## 4. 其他页面

- 长稿配音：SRT/TXT/粘贴导入 + SRT 时间码参考 + 可编辑分句 + 统一声音与模型可用控制 + 30 字试听 + 完整 MP3；不重复堆叠用途说明和步骤条。
- 多人对话：提供“智能提取角色”和“直接识别”两个入口。前者用于分镜稿、对白稿或混杂脚本，调用用户配置的 API 去除非台词内容并在确认弹窗中预览角色、台词和删除类别；后者只在本机拆分“角色名：台词”。确认后仍可编辑角色名和台词，项目统一模型/语言，角色独立声音/语速及模型可用情绪，并支持 30 字试听。
- 我的声音：录音导入 + 选中录音预听 + 命名 + 原文；已创建声音卡片可直接试听或暂停当前参考录音，不展示虚构内置声音。
- 项目与记录：使用固定双栏工作台。左栏只搜索、选择、改名和删除项目，并提供“全部录音”；右栏标题始终显示当前范围，等待中/生成中任务放在“正在处理”，旧失败单独放在“以前未完成”，下方按日期铺开录音版本，提供继续编辑、播放进度、收藏筛选、导出和删除。失败任务可编辑、重试或移除；正在处理的任务必须先取消，避免误删。自动项目和录音使用各自创建时间显示到秒。宽屏录音双列，1280×720 单列；项目和记录分别在栏内滚动，不使用整页下翻。
- 模型管理：三款精选模型卡片；每张卡片简要说明适合场景，状态和动作靠近模型名称，许可使用可阅读的弹窗展示。
- 设置：只保留检查修复、模型位置与迁移、运行设备、导出命名、API配置、检查更新、诊断和软件许可。API配置弹窗只显示 Base URL、Model 与 API Key；保存即启用，新 Key 直接覆盖旧 Key，已保存的 Key 不回显。

## 5. 响应式规则

- `>= 1400px`：生成页主区两列，右侧控制列 320–350px。
- `1120–1399px`：导航缩至 196px，控制卡折为两列控件。
- 高度 `< 800px`：标题与卡片垂直间距收紧 2–4px。
- 150% DPI 以 CSS 像素布局，不使用绝对屏幕坐标。
- 禁止页面级横向滚动；长模型名和路径可换行或省略并保留 tooltip。

## 6. 状态与文案

文案遵循以下规则：

- 导航主创作功能保持同一层级；模型管理单列为“模型”。副标题只用一句短语区分用途，不重复页面正文。侧栏底部只保留“设置”；“支持作者”在设置主体下方使用横向独立区域，不属于本机或维护设置，弹窗只展示本地内置的微信收款码。
- 同一信息只解释一次；标题、卡片、提示和 Toast 不重复表达相同状态。
- 普通输入操作不弹 Toast；后台生成是跨页面长任务，完成后显示带“查看并试听”的成功 Toast，失败时显示不会自动消失的错误 Toast，并提供“查看任务”。点击动作后跳到并高亮对应录音或任务，不强制打断用户当前编辑。
- 按钮直接使用动作名称，如“生成音频”“导出音频”，避免“立即开始”等装饰词。
- 空状态说明下一步，错误状态说明恢复动作。
- Mock、许可和硬件限制必须明确，但不在每个层级重复。

| 技术状态            | 用户文案         |
| ------------------- | ---------------- |
| `not-installed`     | 尚未安装         |
| `downloading`       | 正在下载         |
| `download-paused`   | 下载已暂停       |
| `download-failed`   | 下载未完成       |
| `installing`        | 正在安装         |
| `loading`           | 正在准备模型     |
| `ready`             | 可以使用         |
| `generating`        | 正在生成         |
| `success`           | 已生成           |
| `generation-failed` | 这次没有生成成功 |
| `stopped`           | 已停止           |

失败提示必须给出下一步，不只显示错误码。

## 7. 可访问性

- 所有图标按钮都有中文 `aria-label`。
- 焦点环清晰，键盘可操作。
- 文本与关键控件达到 WCAG AA 目标。
- Toast 使用 `aria-live="polite"`；严重失败使用 `role="alert"`。
- 支持 `prefers-reduced-motion`，关闭位移和缩放，只保留必要淡入。
