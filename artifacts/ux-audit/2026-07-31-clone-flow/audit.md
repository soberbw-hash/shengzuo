# CloneVoice 用户路径审计

审计窗口：1280 × 720  
审计范围：开始创作、我的声音、克隆声音入口  
审计日期：2026-07-31

## 结论

现有界面视觉清爽，但产品组织仍从模型和功能出发，不是从普通用户“用自己的声音说一段文字”的任务出发。克隆声音入口还是死路，属于 P0 问题。

## 发现与修复

1. **P0：克隆声音不可完成。** “设计新声音”只显示未开放提示。改为可操作的三步演示流程：选择或使用示例音频、命名、确认授权。
2. **P1：第一屏先要求理解模型。** 模型名称、显存和下载体积占据首要位置。改为先选声音、再输文字；模型移入“更多设置”。
3. **P1：主导航过多。** 七个同级入口让用户先做产品结构判断。改为“开始创作、我的声音、作品、设置”四个主入口，其余放入“更多功能”。
4. **P1：术语距离用户太远。** “音色库、模型管理、Mock”改为“我的声音、本地引擎、演示版”。
5. **P2：中文字体与小字可读性。** 字体栈优先 HarmonyOS Sans SC，并回退到 Windows 系统字体；主操作说明维持 12px 以上。
6. **P2：玻璃材质使用过多。** 玻璃保留在窗口、导航和环境层；输入、内容与弹窗使用更实的背景，保证对比度。

## 设计依据

- Apple HIG：材质服务于层级与控件，避免透明效果影响内容可读性。
- Microsoft Windows Design：保持可预测导航、清晰操作、键盘与高对比度支持。
- Huawei HarmonyOS Sans：仅作为已安装字体的首选项，不随仓库分发字体文件。
